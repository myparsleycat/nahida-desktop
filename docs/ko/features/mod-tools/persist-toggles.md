# 토글 영구 저장

3DMigoto는 `persist`로 지정된 토글 변수의 상태를 `d3dx_user.ini`에 저장해, 게임을 다시 실행해도 이전 토글 상태를 유지합니다.

하지만 이 값은 모드 INI 파일이 아니라 `d3dx_user.ini`에만 저장됩니다. 따라서 모드를 비활성화한 상태로 Reload(F10)를 실행하면 해당 토글 값이 제거될 수 있으며, 이후 모드를 다시 활성화했을 때 이전 상태가 아닌 모드 INI 파일의 기본값이 적용될 수 있습니다.

## 기능 설명

이 기능을 활성화하면 나히다 데스크탑이 각 Importer의 `d3dx_user.ini` 변경 사항을 감시합니다.

인게임에서 토글을 변경한 뒤 Reload(F10)로 인해 `d3dx_user.ini`가 갱신되면, `d3dx_user.ini`에 저장된 토글 값을 해당 모드의 INI 파일에 자동으로 반영합니다.

그 결과 모드를 비활성화하거나 다시 불러온 뒤에도 이전 토글 상태를 계속 유지할 수 있습니다.

## 복사한 모드와 namespace 분리

자동 namespace 분리는 **namespace 충돌** 영역의 스위치로 켜고 끕니다. 기본값은 꺼짐이며, **토글 영구 저장**도 함께 켜져 있어야 동작합니다. 켜져 있는 동안에는 앱 시작 시, 모드 폴더가 변경될 때, 게임 실행 직전, 그리고 주기적으로 모드 폴더의 INI를 검사하므로 디스크 접근이 늘어납니다. 꺼져 있으면 이 검사를 하지 않으며, **다시 검사** 버튼을 눌렀을 때만 충돌을 확인하고 보고합니다.

서로 다른 모드가 명시적으로 지정한 namespace를 중복 사용하고 안전하게 변경할 수 있다면, 나히다 데스크탑은 비활성 복사본을 포함한 **모든 참여 모드**에 독립적인 namespace를 지정하고 관련 INI 참조를 변경합니다. 앱 밖에서 만든 복사본도 감지하며, 앱을 다시 시작한 뒤에도 확인합니다.

분리는 명시적인 `namespace = ...` 선언에만 적용합니다. 같은 모드 안의 본체 INI와 help·메뉴 INI는 namespace를 공유할 수 있으며, 이것만으로 충돌로 판단하지 않습니다. NTE는 제외합니다. GUI의 모드 이름은 그대로 유지하며 namespace 접미사를 붙이지 않습니다.

게임 실행 중에는 변경을 게임 종료 후로 미룹니다. 충돌 영역에는 **게임 종료 대기 중**, **검토 필요**, **실패**, **복구 필요** 상태와 사유, 세부 정보, 모드·INI 경로가 표시됩니다. Importer별 **다시 검사** 버튼으로 검사를 요청할 수 있습니다. 강제 실행, 게임 종료 기능은 없으며 분리를 위해 F10을 누를 필요도 없습니다.

namespace 매핑은 모드의 `nhd` 메타데이터에 기록합니다. INI 변경에는 백업과 복구 정보를 사용합니다. 복구가 필요하면 파일을 변경하기 전에 표시된 경로와 세부 정보를 확인하세요. 기존 `d3dx_user.ini` 값이 어느 복사본의 상태인지 확실하지 않으면 이전 값을 전달하지 않습니다. 모호한 persist 변수는 복사본에 임의로 할당하지 않고 저장을 건너뛰며 로그에 기록합니다. 충돌하지 않는 다른 변수는 계속 저장됩니다.

자동 분리가 꺼져 있어도 게임 실행 전에는 INI 내용을 읽지 않고 모드 폴더 경계와 트랜잭션 저널을 확인합니다. 미완료이거나 읽을 수 없는 저널이 있으면 해결될 때까지 실행을 차단합니다. 중단된 작업은 **다시 검사**로 복구할 수 있으며, 자동 분리가 꺼져 있어도 복구 기능은 사용할 수 있습니다.
