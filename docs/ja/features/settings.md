# 設定

ナビゲーションレール下部の `設定` を開きます。セクション一覧は左側にあり、一覧の下にアプリのバージョンと `更新を確認` が表示されます。

ほとんどの設定は変更するとすぐに保存されます。プロキシ、GitHub トークン、Nahida Agent の設定は、それぞれの `保存` ボタンで保存します。

`MOD` セクションは [MOD 設定](/ja/features/mod-manager/settings) で説明しています。XXMI の設定は XXMI ページにあります。[XXMI の設定](/ja/others/set-up-xxmi) を参照してください。

## 一般 {#general}

### アプリケーション

| 設定 | 既定値 | 説明 |
|---|---|---|
| `ログイン時に実行` | オフ | Windows にログインするとアプリを起動します。インストール版でのみ表示されます。 |
| `昇格ヘルパー` | オフ | 管理者権限が必要な操作を処理する別のヘルパーを管理者権限で起動します。アプリの起動時に Windows の UAC 確認が表示されます。 |
| `バックグラウンド実行` | オン | すべてのウィンドウを閉じてもアプリをバックグラウンドで実行し続けます。 |
| `タイトルバー作業バッジをクリックで開く` | オン | タイトルバーの作業バッジをクリックすると関連ページを開きます。オフにすると、バッジをつかんでウィンドウを移動できます。 |
| `Mica 背景効果` | オン | ウィンドウの背景に Windows の Mica 効果を使用します。変更するとウィンドウを開き直します。Windows が Mica に対応している場合にのみ表示されます。 |
| `ぼかし効果` | オン | メニュー、ダイアログ、通知、オーバーレイの背後をぼかします。表示が遅い場合はオフにしてください。 |
| `言語` | Windows の言語 | `한국어`、`English`、`日本語`、`中文` から選択します。既定値は、Windows の表示言語がこのいずれかの場合はその言語、それ以外の場合は英語です。 |
| `テーマ` | `システム設定を使用` | `システム設定を使用`、`ライト`、`ダーク` から選択します。 |
| `開始ページ` | `MODマネージャー` | アプリの起動時に表示するページです。`転送`、`GameBanana`、`MODマネージャー`、`ドライブ`、`共有ドライブ` から選択します。`ドライブ` と `共有ドライブ` には nahida.live へのログインが必要です。 |
| `ログレベル` | `Warn` | ログに記録する最低レベルです。`Trace`、`Debug`、`Info`、`Warn`、`Error`、`Fatal` から選択します。 |

[トグルの永続保存](/ja/features/mod-tools/persist-toggles) と Toggle Viewer ジェネレーターの `Toggle Viewer 自動生成` は、アプリが実行し続けている必要があります。どちらかをオンにすると `バックグラウンド実行` もオンになり、どちらかがオンの状態で `バックグラウンド実行` をオフにすると確認が表示されます。

### 更新

| 設定 | 既定値 | 説明 |
|---|---|---|
| `自動更新` | `自動更新` | アプリの更新の扱い方です。 |
| `プレリリースを含める` | オフ | GitHub のプレリリースもアプリの更新として提供します。ドラフトリリースは除外されます。 |
| `更新状態` | | 現在の更新状態を表示します。更新があるかダウンロード済みの場合は `更新をダウンロード` または `更新をインストール` が表示されます。 |

`自動更新` のオプションは次のとおりです。

- `自動更新`: 起動時と 1 時間ごとに更新を確認し、自動的にダウンロードします。
- `更新通知`: 更新を自動的に確認し、ダウンロードはユーザーが選択したときにのみ行います。
- `自動更新オフ`: 更新を自動的に確認またはダウンロードしません。

セクション一覧の下の `更新を確認` を押すと、すぐに確認します。

## ドライブ {#drive}

[ドライブと共有ドライブ](/ja/features/#drive) の設定です。

| 設定 | 既定値 | 説明 |
|---|---|---|
| `名前の並べ替えポリシー` | `自然順 + 空白を無視` | ドライブの項目を名前順に並べるときの空白と数字の扱い方です。`自然順 + 空白を無視` または `標準の自然順` を選択します。 |
| `パスワード自動試行` | オフ | パスワードが必要なリンクを解決するとき、保存されたパスワードを試します。 |
| `パスワード一覧` | 空 | 試すパスワードです。最大 10 個まで保存でき、`追加` で追加します。 |

## アカウント {#account}

ログインしている nahida.live アカウントを表示します。

- `ログイン`: ログインしていないときに表示されます。
- `マイアカウント`: nahida.live のアカウントページを開きます。
- `ログアウト`: アカウントからログアウトします。

サーバーに接続できない場合は、`再試行` で接続をもう一度確認します。

## 転送 {#transfer}

[転送](/ja/features/#transfers) ページの設定です。

| 設定 | 既定値 | 説明 |
|---|---|---|
| `同時ダウンロード数` | 32 | ドライブの転送で同時にダウンロードするファイル数です。範囲は 16–64 です。 |
| `同時アップロード数` | 8 | ドライブの転送で同時にアップロードするファイル数です。範囲は 4–16 です。 |
| `ダウンロード帯域幅制限 (MiB/s)` | 0 | すべての転送を合わせたダウンロード速度の上限です。0 は無制限です。範囲は 0–1024 です。 |
| `転送開始時に転送ページを開く` | オフ | ファイル転送が始まると転送ページを開きます。 |
| `スリープを防止` | オフ | 転送または同期の実行中に Windows がスリープしないようにします。 |

## ネットワーク {#network}

### プロキシ

アプリが送信するすべての外部リクエストをプロキシ経由で送ります。オフの場合は Windows のシステムプロキシ設定に従います。アプリが起動したブラウザー、ゲーム、スクリプトには適用されません。

| 設定 | 説明 |
|---|---|
| `プロキシを使用` | プロキシのオンとオフを切り替えます。 |
| `種類` | `HTTP`、`SOCKS5`、`SOCKS5h` から選択します。`SOCKS5` は宛先の名前をローカルで解決し、`SOCKS5h` はプロキシで解決します。 |
| `ホスト（スキームなし）` | スキーム、パス、ポートを含まないプロキシのホストです。 |
| `ポート` | 1 から 65535 までの整数です。 |
| `ユーザー名（任意）` | パスワードを設定する場合は必要です。 |
| `パスワード（任意）` | `パスワードを削除` は保存時に保存済みのパスワードを削除し、`保存済みパスワードを維持` は維持します。 |

`保存` で保存します。プロキシの変更はアプリの再起動後に適用され、`再起動が必要です` ダイアログで `再起動` を選択できます。

保存されたプロキシ構成を読み込めない場合、正しい構成を入力するかプロキシをオフにして保存し、再起動するまで外部リクエストはブロックされます。

### GitHub トークン

トークンがない場合、GitHub API のリクエストは IP アドレスごとに 1 時間あたり 60 回に制限されます。個人用アクセストークンを使うと 1 時間あたり 5,000 回に増えます。アプリは公開リポジトリのみを読み取るため、Fine-grained トークンに追加の権限は必要ありません。

1. `GitHub でトークンを作成` を押してトークンを作成します。
2. `個人用アクセストークン` に入力し、`保存` を押します。

トークンは現在の Windows ユーザー向けに暗号化して保存されます。`トークンを削除` で削除します。GitHub が保存済みのトークンを拒否した場合や、現在の Windows ユーザーで復号できない場合は、新しいトークンを入力するまで認証なしでリクエストします。

## ツール {#tools}

| 設定 | 既定値 | 説明 |
|---|---|---|
| `更新通知` (Wuwa Mod Fixer) | オン | [Wuwa Mod Fixer](/ja/features/mod-manager/mod-tools#fix) の更新があるときに通知を表示します。バックグラウンドの更新はこの設定に関係なく 1 時間ごとに実行されます。 |

## Nahida Agent {#nahida-agent}

Nahida Agent が使用するモデルを設定します。プロバイダーとモデルを設定すると、ナビゲーションレールに Nahida Agent が表示されます。

### LLM プロバイダー

| 設定 | 説明 |
|---|---|
| `プロバイダー` | モデル一覧にある組み込みのプロバイダー、または `カスタム` を選択します。認証情報が保存されたプロバイダーには `接続済み` が表示されます。 |
| `モデル` | 一覧からモデルを選ぶか、モデル ID を入力します。欄の下にモデル一覧の日付が表示され、`モデル一覧を更新` で更新します。 |
| `推論` | 推論レベルです。組み込みのプロバイダーでは、モデルが対応するレベルのみ表示されます。 |
| `エージェントのスクリプトを確認なしで実行` | エージェントが書いた Python と PowerShell のスクリプトを、毎回承認を求めずに実行します。スクリプトは Windows アカウントの権限で実行され、エージェントのフォルダーに制限されません。 |
| `API キー` | `現在の値を維持`（または `設定済みキーを維持`）、`置換`、`クリア` から選択します。ChatGPT でのサインインに対応するプロバイダーでは `ChatGPT Pro/Plus` も選択できます。`ChatGPT でサインイン` を押し、ブラウザーでサインインを完了してください。ブラウザーが開かない場合は `リンクをコピー` を使います。 |

`カスタム` を選択すると、次の設定も表示されます。組み込みのプロバイダーでは、これらの値をモデル一覧から取得します。

| 設定 | 説明 |
|---|---|
| `プロトコル` | `OpenAI Responses`、`OpenAI-compatible`、`Anthropic Messages` から選択します。 |
| `エンドポイント` | API のベース URL です。 |
| `モデルが画像入力に対応` | 添付した画像とツールが返したスクリーンショットをモデルに送ります。モデルが画像入力に対応している場合にのみオンにしてください。 |
| `コンテキストウィンドウ`、`最大出力トークン` | モデルのトークン上限です。 |
| `カスタムヘッダー` | カスタムエンドポイントへのリクエストにのみ付けるヘッダーです。`暗号化して保存` を選ぶと値を暗号化します。 |

`接続テスト` はテストリクエストを送り、モデルと応答時間を表示します。`保存` でプロバイダーの設定を保存します。

### MCP

エージェントがツールとして使う MCP サーバーを追加します。有効な MCP ツールは自動的に実行され、Nahida のファイルサンドボックス外の権限を持つ場合があります。

`サーバーを追加` を押し、`トランスポート` を選択します。

- `stdio`: `実行ファイル`、`引数（1 行に 1 つ）`、`作業ディレクトリ` を入力します。
- `Streamable HTTP`: サーバーの URL を入力します。
- `Blender (内蔵)`: ローカルソケットで Blender MCP アドオンに接続します。先に Blender でアドオンの設定からブリッジサーバーを起動してください。

`項目を追加` で名前と値を追加し、`暗号化して保存` を選ぶと値を暗号化します。`有効` をオンにして `保存` を押します。保存したサーバーの `接続テスト` は、サーバーが提供するツールの数を表示します。

### スキル

組み込みスキルとユーザースキルを表示します。スキルはモデルが要求したときに読み込まれます。`ユーザースキルフォルダーを開く` はユーザースキルのフォルダーを開き、`再読み込み` はフォルダーをもう一度読み込みます。

## 詳細 {#advanced}

保存されているすべての設定をキーと値で表示します。`設定キーを検索...` でキーを検索し、`編集` ボタンで生の値を変更します。

::: warning
ここで入力した値はそのまま保存されます。誤った値はアプリの動作を変えることがあります。
:::

プロキシと GitHub トークンは一覧に表示されず、[ネットワーク](#network) で変更します。キーに `password`、`token`、`secret`、`credentials`、`api_key` を含む値は `********` と表示されます。

## 問題を報告 {#report-a-problem}

問題の報告を開発者に送ります。

| 項目 | 説明 |
|---|---|
| `分類` | `Desktop アプリの問題`、`Nahida サービスの問題`、`XXMI ライブラリの問題` から選択します。 |
| `内容` | 何が起きたかと再現手順です。必須項目です。 |
| `添付` | `ファイルを追加` で画像、動画、テキストファイル、zip アーカイブを添付します。`MOD フォルダーを追加` は問題のある MOD のフォルダーを添付します。nahida.live へのログインが必要で、ドライブが受け付けない形式のファイルは除外されます。 |
| `ログを添付` | 既定でオンです。アプリのログを添付し、PC のユーザー名などの機密情報は匿名化されます。 |

文字数と添付の上限はサーバーから読み込まれ、各項目の横に表示されます。`送信` で送信し、送信中は `キャンセル` で中止できます。
