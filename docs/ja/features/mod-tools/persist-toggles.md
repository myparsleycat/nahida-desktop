# トグル状態の永続保存

3DMigoto は `persist` として指定されたトグル変数の状態を `d3dx_user.ini` に保存するため、ゲームを再起動しても以前のトグル状態を維持できます。

ただし、この値は MOD の INI ファイルではなく `d3dx_user.ini` にのみ保存されます。そのため、MOD を無効化した状態で Reload (`F10`) を実行すると、そのトグル値が削除される場合があります。後で MOD を再度有効化したとき、以前の状態ではなく MOD の INI ファイルにある既定値が適用されることがあります。

## 機能の説明

この機能を有効にすると、Nahida Desktop は各 Importer の `d3dx_user.ini` の変更を監視します。

ゲーム内でトグルを変更し、Reload (`F10`) によって `d3dx_user.ini` が更新されると、Nahida Desktop は `d3dx_user.ini` に保存されたトグル値を対応する MOD の INI ファイルへ自動的に反映します。

その結果、MOD を無効化した後や再読み込み後でも、以前のトグル状態を維持できます。

## コピーした MOD と namespace の分離

namespace の自動分離は、**namespace の競合** 欄のスイッチで切り替えます。既定ではオフで、**トグル状態の永続保存** も有効な場合にのみ動作します。オンの間は、アプリの起動時、MOD フォルダーの変更時、ゲーム起動の直前、および定期的に MOD フォルダー内の INI をスキャンするため、ディスクアクセスが増えます。オフの間はこれらのスキャンを行わず、**再検査** ボタンを押したときだけ競合を確認して報告します。

異なる MOD が明示的な namespace を重複して使用し、安全に変更できる場合、Nahida Desktop は無効なコピーも含む **すべての参加 MOD** に独立した namespace を割り当て、関連する INI の参照を更新します。アプリの外で作成したコピーも検出し、アプリの再起動後も確認します。

分離の対象は、明示的な `namespace = ...` 宣言のみです。同じ MOD 内の本体 INI と help・メニュー INI は namespace を共有でき、それだけでは競合と判断しません。NTE は対象外です。GUI の MOD 名は変わらず、namespace の接尾辞は追加しません。

ゲームの実行中は、変更をゲーム終了後まで延期します。競合欄には **ゲームの終了待ち**、**確認が必要**、**失敗**、**復旧が必要** の状態と、理由、詳細、対象の MOD・INI パスを表示します。Importer ごとの **再検査** ボタンで確認を依頼できます。強制実行、ゲーム終了操作はなく、分離のために F10 を押す必要もありません。

namespace の対応関係は MOD の `nhd` メタデータに記録します。INI の変更にはバックアップと復旧情報を使用します。復旧が必要な場合は、ファイルを変更する前に表示されたパスと詳細を確認してください。古い `d3dx_user.ini` の値がどのコピーに属するか不確かな場合、以前の値は移しません。曖昧な永続変数はコピーに割り当てず、保存をスキップしてログに記録します。競合しない他の変数は引き続き保存されます。

自動分離がオフでも、ゲーム起動前に INI の内容を読まず、MOD フォルダーの境界とトランザクションの記録を確認します。未完了または読み取れない記録がある場合は、解決するまで起動を止めます。中断された処理は **再検査** で復旧できます。自動分離がオフでも復旧機能は利用できます。
